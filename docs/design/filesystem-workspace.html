Filesystem Workspace

把 CMaster 的员工端从“带侧栏的聊天页”演进为真正受权限约束的 Agent 工作空间：Employee 在 Conversation 前选择私有 Workspace 和 Git Worktree，Agent 只能在固定 Workspace Revision 的隔离 Sandbox 中读取文件或提出 Change Set。

1. 问题与目标

Slice 5 验收证明了恢复、隐私、Run、治理和 Artifact 语义，但页面仍是传统后台式 Conversation UI；更关键的是，旧设计把“Employee Workspace”当作整个界面名称，没有表达 Employee 在开始 Conversation 前必须选择的文件权限范围。

目标：Workspace 成为单个 Employee Principal 私有拥有的、服务端管理的文件系统与权限边界。Employee Experience 是整个员工端产品；两者不再混名。

术语定义与不变量禁止混用
Employee Experience员工使用 CMaster 的完整 Web 体验。不是 Workspace。
Workspace一个 Employee Principal 私有拥有的文件系统根与权限边界；可包含多次 Conversation。不是 Organization、共享团队空间或标签。
Repository BindingWorkspace 与最多一个受信任 Git Repository 的受治理关联。不是 Credential 或 Worktree。
Git WorktreeRepository 的独立 Branch 工作目录；Conversation 固定一个 Worktree。不是 Workspace。
Workspace Revision一个 Working Root 的一致不可变状态标识；Run 固定读取它。不是 Git Commit 或 Artifact Version。
Workspace File根目录内可变工作材料。不是 Artifact。
Workspace Change Set针对一个 Revision 的不可变文件变更提案，整体批准或拒绝。不是已应用文件、Git Commit 或可编辑审批表。
Artifact Version明确发布的不可变交付物版本，固定属于一个 Workspace。不是可变 Workspace File。

3. 权限与隔离

Workspace 位于 Employee Principal 私有边界之下，不支持 Workspace Membership、跨 Employee 授权或默认共享。有效能力为以下交集：

Organization Policy 上限
∩ Principal Entitlement
∩ Workspace Operation Mode
∩ Run 启动时模式上限
∩ Agent Revision Tool Grant
∩ Policy Decision
∩ Delegation 限制

Observe

允许列目录、搜索和读取；禁止文件写入。

Edit with Confirmation（默认）

读取可自动进行；写入形成 Change Set，批准前不修改文件。

Trusted Automation

仍形成 Change Set；Policy 允许时自动批准应用，不绕过 Revision、审计或冲突检测。

  • 权限提升只影响新 Run；当前 Run 不静默扩权。
  • 权限收缩立即限制尚未执行的 Tool Call；已完成副作用不回滚。
  • Push、高风险命令、网络和 Credential 可被 Policy 强制确认，Trusted Automation 也不能绕过。

4. Workspace 创建与选择

  1. 首次进入且没有 Workspace 时显示 Chooser，不创建无范围 Conversation。
  2. Employee 选择“空 Workspace”或“从受信任 Git Repository 创建”。
  3. Git 创建选择 Connector、Repository、Branch、显示名称和 Operation Mode；客户端不能提交 Server 绝对路径。
  4. Server 异步 Provision；完成前不允许创建 Conversation。
  5. 已有 Workspace 时恢复上次选择，但 Switcher 始终显示当前范围。
  6. 一个 Workspace 包含多次 Conversation；Workspace Switcher 和 Worktree Switcher 是导航，不改变已有 Conversation 归属。
首版来源：空目录 + 受信任 Git Repository。上传、企业存储导入和本机目录 Companion 后置。

5. Repository 与 Worktree

  • 一个 Workspace 最多绑定一个根 Repository，可包含多个 Git Worktree。
  • 新 Conversation 默认使用当前 Worktree，也可创建隔离 Worktree；已有写入型 Run 时 UI 主动推荐隔离。
  • Conversation 创建后固定 Worktree；一个 Run 不得修改多个 Worktree。
  • 多个 Conversation 可并行读取和产生 Change Set；实际应用按 Revision 串行校验。
  • 不重叠的 stale Change Set 可确定性重放；重叠或无法证明安全时进入冲突，不盲目覆盖。
  • Apply Change Set、Git Commit、Push、Create PR 和 Merge 是独立受治理动作；Push 始终确认。
  • 隔离 Worktree 不自动 Commit、Merge 或删除。删除前处理未应用 Change Set 和未提交状态；删除后 Conversation 历史只读。

6. Run、Revision 与 Sandbox

Run accepted
  ├─ workspaceId
  ├─ worktreeId / defaultWorkingRootId
  ├─ baseWorkspaceRevisionId
  ├─ maxWorkspaceOperationMode
  └─ pinned Agent Revision / Policy versions
        ↓
Sandbox
  ├─ /workspace  当前固定 Revision
  ├─ /runtime    只读
  ├─ /tmp        Invocation 私有
  └─ host paths  不可见
  • Run 默认读取固定 Revision 的一致快照；应用 Change Set 后通过显式记录推进。
  • 每个 Run 只挂载一个 Working Root；路径规范化、符号链接、Git hooks、子进程和挂载均不能逃逸。
  • 默认无外网；网络通过受治理能力开放。Credential 使用短期 Lease，不写入 Workspace。
  • Observe 的 Workspace mount 只读；mutating Run 只能写 Invocation-private ephemeral overlay。overlay finalize 为不可变 Change Set 后，只有中央 apply transition 能改变共享文件。
  • Workspace Files/Revisions 是共享持久权威数据，不依赖单 Worker 磁盘；其他 Worker 可恢复 Sandbox 与未完成 overlay。
  • 该硬安全决策记录于 ADR-0045。

7. Context 与文件访问

  • Workspace 定义 Agent 能访问哪里，不等于全部文件自动进入 Model Context。
  • Agent 通过 list/search/read Tool 按需读取，Context Manifest 记录实际文件、Revision、hash 和纳入方式。
  • .cmasterignore 是强访问限制；Git Workspace 同时参考 .gitignore。
  • 默认排除 .git、Secret、依赖缓存、构建产物、二进制和超限文件。
  • Employee 可见“本次读取的文件”，但看不到原始 Prompt 或 Chain-of-Thought；文件内容不进普通遥测。

8. Change Set 与治理

  1. Agent 针对固定 Workspace Revision 生成不可变 Change Set。
  2. Edit with Confirmation 创建不可变 Approval Subject；批准前文件不变。
  3. Employee 可整体批准、拒绝或要求调整；要求调整会创建新 Change Set。
  4. 应用时重新校验 Principal、Workspace Mode、Policy 和 Base Revision。
  5. 成功原子产生新 Workspace Revision；失败返回结构化 conflict/denied/stale 结果。
  6. Trusted Automation 走同一路径但可自动批准；不存在第二写路径。

首版不提供逐文件或逐 Hunk 批准，也不允许在审批表中直接编辑内容。

9. Workspace File 与 Artifact

  • Workspace File 可反复修改；不会自动成为 Artifact。
  • 明确发布时，从特定 Worktree/Workspace Revision/path 创建不可变 Artifact Version。
  • Artifact 固定属于 Workspace；同 Workspace 多个 Conversation 可引用。
  • 跨 Workspace 使用必须显式治理复制并创建新的 Artifact；不直接共享。
  • Worktree 删除不删除 Artifact；Message 继续引用确切 Artifact Version。
  • 首版 Browser 只读预览 Workspace File，不建设 IDE；Employee 通过 Conversation 和 Change Set 修改。

10. Pending 与生命周期

  • 全局 Pending Inbox 聚合该 Employee 所有 Workspace 的 Interrupt，并按 Workspace 分组。
  • Workspace 内显示局部 Pending；点击恢复准确 Workspace、Worktree、Conversation、Run。
  • Archive 禁止新 Conversation/Run/修改但保留可读历史，可恢复。
  • Delete 仅对已归档且无 Active/Waiting Run 的 Workspace开放；要求明确确认并遵循 Retention/GC。
  • Delete 不推送、不删除 Remote Branch，也不抹除必须保留的 Audit/Run Event。

11. Agent 选择

  • Workspace 配置 Default Agent 与 Allowed Agents。
  • 新 Conversation 使用默认 Agent；Composer 可为下一 Run 选择允许的 Agent。
  • Agent 切换仅影响未来 Run；每个 Run 固定实际 Agent Revision。
  • 子 Agent 仍创建 child Invocation，不创建新 Conversation，也不能突破 Workspace。

13. UI 技术边界

  • 真实组件基线：AI Elements 1.9 Registry、shadcn/ui、Tailwind CSS、Lucide Icons。
  • 优先采用 Conversation、Message、Prompt Input、Tool、Confirmation、Plan、Artifact 与 shadcn Sidebar/Tabs/Sheet/Dialog/Dropdown。
  • 不再自行重画 Button、Sidebar、Dialog、Tooltip、Composer 等基础组件。
  • CMaster 继续拥有 Contracts、View Models、TanStack Query 状态、sequence-aware UI Projection 和 Command recovery。
  • 不使用默认 useChat 接管 Message/Run 生命周期；AI SDK/AI Elements 类型在 Web Adapter 终止。
  • 不展示原始 Chain-of-Thought、Prompt、Tool payload 或 Provider raw error。
  • 原型是 primary source，不直接提升为生产代码；生产实现按公开 Seam 和 TDD 重写。

14. Workspaces Module

新增 packages/workspaces 深 Module。它隐藏 Git、持久内容、Revision、冲突、Change Set、Provisioning 与 Sandbox materialization 的复杂性；调用者不学习路径或存储布局。

Module拥有禁止
WorkspacesWorkspace、Repository Binding、Worktree、Revision、File metadata、Change Set、Operation Mode、lifecycle不拥有 Conversation、Run、Approval、Artifact
ConversationsWorkspace/Worktree-scoped Conversation 与 Message不读 Workspace 表或文件
Execution固定 Run scope、Checkpoint、事件与恢复不管理 Git 或拼接路径
Tools通用 Tool Runtime 与 Ledger不绕过 Workspace capability
Context按需选择 Workspace File references不拥有文件或全量注入
ArtifactsWorkspace-scoped Artifact/Version/Content不把 mutable file 当 Artifact
GovernanceChange Set/Commit/Push Approval 与 Policy不应用文件变更

15. 实施顺序

  1. Foundation：Workspaces Domain、PostgreSQL schema、private list/create/archive、空 Workspace 持久内容。
  2. Git Provisioning：Repository Binding、clone/fetch、单 Repository、多 Worktree、状态与 Credential seam。
  3. Sandbox Read：隔离 Runtime、Workspace Revision materialization、list/search/read、.cmasterignore、Context Manifest。
  4. Change Sets：propose/approve/apply、conflict、Operation Mode、Trusted auto-apply、恢复。
  5. Conversation/Run Scope：Workspace/Worktree URL、Conversation ownership、Run pinning、Agent selection。
  6. Git Delivery：Commit/Push/PR/Merge 独立治理与 uncertain outcome。
  7. Artifact/Pending Scope：Workspace Artifact publish/copy、全局与局部 Pending。
  8. Employee Experience：按 Balanced Workspace A 用真实组件和 View Model Adapter 重写。
  9. Release Gate：真实 PostgreSQL/Worker/Sandbox/Git fixture/Browser 闭环；删除旧 Employee Workspace UI 和写路径。

每项是独立短期分支/PR；前置能力通过后才开始下一项，不建立长期总重构分支，不长期双写，不迁移当前开发原型数据。

16. 发布验收

  1. 首次 Employee 创建空 Workspace 和 Git Workspace；Provisioning/失败/恢复行为明确。
  2. Workspace/Worktree Switcher 只显示 owner 数据；Conversation 创建前 scope 已确定且 URL 可恢复。
  3. 同 Workspace 多 Conversation、同 Repository 多 Worktree 工作；Run 只访问固定 Revision 和一个 Working Root。
  4. Observe 禁写；Edit 模式批准前无文件变化；Trusted 模式仍产生自动应用 Change Set。
  5. 并发不重叠 Change Set 可确定性应用，重叠 stale proposal 进入 conflict 且不覆盖。
  6. Sandbox 阻止绝对路径、../、symlink、hook、subprocess 和 network escape；Worker 重启可恢复。
  7. Git Apply/Commit/Push/PR/Merge 分离；Push unknown outcome 不盲重试。
  8. Workspace File 可变、Artifact Version 不可变；跨 Workspace 显式复制；Worktree 删除后 Artifact 存续。
  9. AI Elements/shadcn Employee Experience 完成 desktop/mobile、zh-CN/en-US、Light/Dark、keyboard、axe。
  10. Contracts、Module Interface、PostgreSQL、Sandbox、Git Adapter、Projection、Browser 和恢复门禁全部通过后才替换旧 UI。

17. 否决与延期

明确否决

  • Workspace 只是前端筛选标签
  • Workspace 跨 Employee 共享或 Membership
  • 浏览器直接提交 Server 绝对路径
  • 宿主机运行 + 路径前缀检查
  • 一个 Run 修改多个 Worktree
  • Trusted 模式绕过 Change Set
  • Change Set 自动 Commit/Push/Merge
  • 把所有文件自动放入 Prompt
  • 用 Workspace File 替代 Artifact
  • 只换皮但伪造后端 Workspace

首版延期

  • Employee 本机目录 Companion
  • 文件/目录上传和企业存储导入
  • multi-repository / multi-root Workspace
  • Browser 文本或代码 IDE
  • 逐文件、逐 Hunk Change Set 批准
  • Workspace 跨 Principal 分享
  • 自动 Merge 或自动 Worktree 清理
  • 复杂二进制文件预览
