1. 产品目标与主验收场景

  1. Employee 打开 Workspace 首页，从最近 Conversation、待处理和 Artifact 摘要进入工作。
  2. Employee 新建 Conversation；只有首次发送时才持久化 Conversation。
  3. UI 依次、可恢复地追加 Employee Message 并创建以该 Message 为 Trigger 的 Run。
  4. Conversation Thread 展示临时 Assistant Draft；Run Detail 展示员工可理解的状态、Tool Activity 和 Timeline。
  5. 若 Run 等待 Employee Confirmation 或 Uncertain Tool Outcome Review，可在 Conversation 或“待处理”入口解决。
  6. 成功后，权威 Assistant Message 原子替换 Draft，并展示按需加载的确切 Artifact Version Card。
  7. Employee 在同一 Conversation 继续第二个 Run；刷新、断流和 Worker 恢复不复制 Run、Message 或 Artifact。
  8. 同 Organization 的其他 Principal 无法读取该 Conversation 及其 Message、Run 和 Workspace Projection。
范围原则：遵循主流 Conversation 产品习惯以降低学习成本；CMaster 的差异只用于准确表达持久 Run、治理、恢复和版本化 Artifact。桌面体验完整，手机交付最小核心，不提前建设搜索、共享、删除、通知或管理能力。

2. 领域语义与产品层级

概念Employee Workspace 中的角色禁止混用
Conversation首要工作容器；包含有序、不可变 Message，默认创建者私有。不是 Run、Chat Session 或 Organization 共享空间。
MessageConversation 中已提交的员工可见事实。不是流式 Draft 或 Run output buffer。
Run一个 Message 工作请求的一次尝试；同一 Message 可有多个明确的历史尝试。不是 Conversation，网络恢复也不是新 Run。
Assistant DraftUI Projection 中当前 generation 的临时输出。不是 Message，不进入 Conversation 事实历史。
Employee Confirmation对一个不可变 Approval Subject 的确认或拒绝。不是长期权限或参数编辑。
Uncertain Tool Outcome Review决定是否带着不确定性继续。不是 Approval，也不能改写 Tool Outcome。
Artifact Reference从 Message 或 Library 打开一个确切 Artifact Version。不是浮动 latest、Attachment payload 或 storage key。
待处理Presentation 层对未解决 Interrupt 的聚合入口。不创建 PendingAction 领域对象。
访问决定：Conversation 默认创建者私有。Organization scope 只提供隔离，不构成共享授权；另一 Principal 的猜测读取返回与不存在相同的 404。见 ADR-0044。

5. Conversation 与 Composer 语义

一次一个活跃 Run：Employee UI 在同一 Conversation 有 accepted | queued | running | waiting Run 时禁用 Composer并解释原因；Server Contract 不把它提升为并发禁止规则，外部产生的多个活跃 Run 必须全部可见。

新 Conversation

  1. /new 只建立本地 Draft，不产生 Server 数据。
  2. 首次发送生成并在 sessionStorage 保存本次 Conversation、Message、Run Command IDs 与阶段。
  3. 依次创建 Conversation、追加 Message、创建 Run；未知响应先查 Server，再以相同 idempotency key 恢复。
  4. 成功后替换为正式 Conversation URL 并清除已提交 Draft。

标题

首条 Employee Message 经空白归一化和 Unicode 安全截断后确定性生成一次初始标题，不调用 Model；Employee 可显式重命名。自动命名不随后续 Message 改写。

键盘与 Draft

  • Enter 发送，Shift + Enter 换行；IME composition 期间绝不发送。
  • 始终提供可见发送按钮；空白不可发送，接近 32 KiB 时提示。
  • Draft 按 Conversation 保存在当前标签页的 sessionStorage；刷新/切换可恢复，发送后删除，关闭标签页后由浏览器清理。
  • Draft 不进入 Server、Query Cache、日志、遥测或 Run Event。

Message 已保存、Run 未创建

Message 保持可见并标记“尚未运行”，Employee 可针对原 Message 恢复创建 Run。网络恢复复用原 Command ID；Employee 明确点击“再次运行”才使用新 Command ID 创建同一 Trigger Message 的新 Run attempt。

6. 长 Conversation、选择与滚动

  • 首屏读取最新 50 条 Message，按 sequence 正序展示；beforeSequence 向上加载更早页面。
  • 插入历史页保持视觉锚点。Employee 接近底部时跟随新内容；阅读历史时不抢滚动，只显示“有新内容”。
  • Conversation 列表使用 opaque cursor，服务端稳定排序基于 (updatedAt, conversationId)。
  • 列表显示标题、作者、有界纯文本预览、最近活动、活跃/待处理状态；Artifact-only 使用本地化通用文案，不引入 unread。
  • 新 Run 自动成为选中 Run。普通 Conversation URL 优先提示待处理，其次活跃 Run，否则不自动展开详情。
  • 每个触发 Message 可打开其历史 Run attempts；多个外部活跃 Run 不隐藏。
  • Message 和 Timeline 支持虚拟化，但必须保持语义顺序、Focus 和合理 overscan。

8. Assistant Draft 与最终 Message

  • Output Delta 只更新标记“生成中”的临时 Draft，不追加伪 Message。
  • Fallback/recovery 的 reset 清空旧 generation，显示自然文案“正在重新生成”，不保留被丢弃文本。
  • 成功且权威 Assistant Message 可读后，以完整 Message 原子替换 Draft，文本和 Artifact References 同时出现。
  • 失败或取消时删除 Draft，只保留结构化结果；部分输出不冒充 Message。
  • 屏幕阅读器不逐 token 播报；可见更新节流，完成时通知。

9. Run Timeline 与治理交互

默认工作语义：Timeline 展示请求、Context 准备、Agent、Tool、Approval、Artifact、Fallback 和终态，不展示 raw canonical event type、Chain-of-Thought、Prompt、Checkpoint、Lease、Outbox 或 Provider raw error。

可展开技术详情只包含安全 ID、时间、持续时间、Agent/Model display name、Fallback、聚合 usage、安全错误码和 correlation ID。

待处理

  • Confirmation 卡片允许确认或拒绝；卡片本身已是一次清晰确认，不再叠加第二个 Dialog。
  • Uncertain Outcome 卡片只允许带着不确定性继续或返回；明确说明不会重试原 ToolCall。
  • Cancel 使用一次可访问 Dialog，说明取消不会撤销已发生 Tool effect。
  • 没有批量确认、修改参数、永久允许或把不确定结果改写为成功。

Tool Renderer

使用 AI Elements Tool 视觉建立高质量通用 Renderer。Artifact 创建成功通过独立 Artifact Card 呈现；不为待替换的 current-time、text-statistics、HTTP-fetch 验证 Tool 建专用 UI。未知 Tool 使用通用 Fallback。

10. Artifact Library、预览与下载

  • Library 只列出 trusted Principal 可读的私有 Artifact，使用 opaque cursor 分页。
  • Message Card 默认不读取正文；Employee 主动预览时才获取确切 Version 内容。
  • 桌面预览使用右侧面板，手机使用全屏路由；关闭后恢复先前 Run Detail 与 Focus。
  • 正式预览只支持 text/plain; charset=utf-8 和 text/markdown; charset=utf-8。
  • Markdown 支持常用 GFM，但禁用 raw HTML、script、remote image 和危险 scheme；外链安全打开并明确标识。
  • PDF、Office、图片、音视频、HTML、JSON/CSV 专用视图、压缩包和未知类型只显示 metadata 与下载。
  • 预览和下载读取同一 Version；?disposition=attachment 由 Server 生成安全文件名并设置 nosniff，Browser 不能提供文件名。
  • Range 对预览和下载保持一致，不创建派生 Blob。

11. UI Framework、Design System 与文案

首个实现：AI Elements + shadcn/ui 薄适配。只引入需要的 Registry Components，尽量保持上游源码，通过 props、className、CSS Variables 和 semantic tokens 定制；CMaster 状态与业务组合留在 Feature 层。
采用适配后采用不采用
Conversation、Message、PromptInput、Tool、Confirmation 的成熟视觉/交互Artifact visual shell、AI SDK hook（仅当服从 CMaster Snapshot/sequence）raw Chain-of-Thought、直接 Provider reasoning、默认 useChat 业务生命周期

AI Elements 的 Attachment、Artifact、Tool 和 Confirmation 类型不进入 Domain、Contracts 或 Projection。大量修改的组件提升为明确 CMaster Feature Component，不继续伪装成上游组件。升级不自动追随 latest；指定版本、查看 diff 并通过质量门禁。

  • 视觉：专业、克制、内容优先、中等密度，遵循主流 SaaS/Conversation 产品习惯。
  • 主题：System/Light/Dark，选择只保存非敏感偏好；两种主题独立满足对比度。
  • 语言：实际交付 zh-CN 和 en-US，Browser 初选、Employee 可切换；URL 无 locale prefix。
  • 文案：自然、简洁、具体，不拟人化，不使用“智能分析”“AI 正在思考”等机器或营销语气；错误说明事实、保存状态和下一步。
  • Server 返回稳定 code 和安全参数；日期、数字、时间与 usage 使用 Intl。
  • 动效只用于状态和定位；reduced motion 下关闭非必要动画。

15. 网络恢复与缓存一致性

  • Query 可有限指数退避并保留旧缓存；UI Stream 以最后 sequence 自动重连。
  • 检测 gap 或无法续接时重新获取 Projection Snapshot 并替换本地投影。
  • Command 不使用通用盲重试；保存本 operation idempotency key，未知结果先查事实再决定是否以同 key 重发。
  • 离线时显示横幅、禁用发送/处理、保留 session Draft；不实现离线队列。
  • 409 表示状态已变化时重新同步，不统一显示“系统错误”。
  • 每个选中活跃 Run 只维持一个 Workspace UI Stream，不同时打开 canonical SSE。

16. 安全与遥测

  • Workspace Query 从 trusted Server identity 获取 Organization/Principal；Browser 不能声明 owner。
  • Conversation/Message/Run/Projection 同 Organization 跨 Principal与不存在返回相同 404。
  • Artifact 继续独立执行精确 Version 授权。
  • 不引入 Session Replay、DOM 采集或通用第三方行为分析。
  • Slice 5 只定义 ClientObservability 安全 Interface 与 no-op Adapter。
  • 允许稳定 Feature 名、计数、延迟、reconnect/gap、safe result code、fallback type、Web Vitals 和 correlation ID。
  • 禁止 Message/Draft/title/preview、Artifact title/body/hash、Tool input、Approval details、DOM、截图和键盘输入。

Browser → same-origin CMaster telemetry intake
        → internal OpenTelemetry Collector

Browser 不持有 Collector Credential；遥测失败不影响 Conversation 或 Run。

17. Feature Flag 生命周期

CMASTER_EMPLOYEE_WORKSPACE_ENABLED=false

该 Flag 依赖 Next Architecture、AI SDK Runtime、Tool Runtime 和 Context/Artifacts；组合无效时启动失败。关闭时保留 Slice 4 最小验证体验和现有 Contract，新的 Projection 与完整 Shell 不挂载。它不拆成页面级 Flags。

19. 发布验收

  1. 持续 Conversation 主流程完成两次 Run、Artifact 创建/预览/下载，并固定 exact Version。
  2. 流式中刷新、SSE gap、Message 已保存但 Run 未启动均恢复原事实且不重复。
  3. retryable failure 的“再次运行”创建新 attempt；网络恢复不创建新 Run。
  4. Confirmation、Uncertain Outcome 和 Cancel 的语义、Focus 与幂等闭环正确。
  5. 同 Organization 另一 Principal 无法读取 Conversation、Message、Run、Projection 和私有 Artifact。
  6. Desktop 完整；Mobile 核心；zh-CN/en-US；System/Light/Dark；keyboard/reduced-motion/axe 通过。
  7. 性能 Fixture 不发生整树流式重渲染；未知 Renderer/Event 不崩溃。
  8. Contract drift、Module boundaries、lint、typecheck、build、dev compile smoke、unit/component、PostgreSQL integration 和 Browser E2E 全部通过。

  • 上传、PDF/Office/image preview、derivative、在线编辑、Artifact 分享/删除
  • Browser/OS Push、Service Worker、邮件/IM 通知、离线发送队列
  • Task 页面、Admin 功能、OIDC/roles、生产遥测导出
  • 高级移动视觉/手势/筛选、完整设备矩阵
  • 用户可拖动布局、Command Palette、mention、slash command、语音和富文本 Composer

明确否决

  • Run-centric 主导航或顶层 Run 正式路由
  • Browser 拼接 N+1 Module queries 或直接查后端私有结构
  • React 解释 canonical Event、AI SDK 类型成为产品 Contract
  • 默认 useChat 接管 Message/Run 生命周期
  • raw Chain-of-Thought/Provider reasoning 展示
  • Server Actions 建立第二条业务写路径
  • Conversation 在 Organization 内默认共享
  • 一个 Mega Workspace DTO、UI Projection 表预建、自动依赖更新

22. 决策理由摘要

决定理由
Conversation-centricConversation 是持续员工事实；Run 只是一次工作尝试。
private by defaultOrganization 隔离不等于共享授权；未来协作需要显式 Policy。
Workspace Projection避免 Browser N+1 与短暂矛盾，同时保持 Module 表所有权。
按需 Projection Snapshot先复用状态/Event，避免无性能证据时引入第二份事务性状态。
AI Elements 薄适配获得主流 AI 交互、降低建设成本，但不让框架改写领域语义。
same-origin HTTP降低 Session Cookie、CORS 与 SSE 部署复杂度，不创建 BFF。
多短 PR降低巨大 UI Slice 的评审、集成和回滚风险。
