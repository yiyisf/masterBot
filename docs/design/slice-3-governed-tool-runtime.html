Governed Tool Runtime

在既有 Run、Invocation、AI SDK Runtime 和 PostgreSQL 恢复语义上，建立统一、可审计、可确认、可恢复的 Tool 执行路径。

1. 目标与边界

本 Slice 交付

  • Tool Catalog、Tool Runtime、Tool-call Ledger
  • 固定 baseline Policy 与 Employee Confirmation
  • Credential Broker 最小 Seam
  • AI SDK 顺序 Tool Loop
  • Execution Checkpoint、Interrupt 与等待恢复
  • 最小 Run 页面确认 UI
  • 不可生产配置的 Provider Host 协议骨架

明确不交付

  • 本地逐 Principal/逐 Tool RBAC
  • 经理审批、四眼审批、Approval Center
  • Policy DSL、OPA/Cedar、Admin CRUD
  • Agent Skills Parser、Legacy Adapter、MCP
  • 可配置外部 executable 或完整沙箱
  • 企业 Vault、Credential 管理 UI
  • 并行 Tool dispatch、子 Agent、Artifact
首版原则：按已接受的数据模型、Module Interface 和 ADR 实现最小闭环。规范要求的授权、幂等、副作用恢复和安全不是“极端场景”；未规划的业务规则和管理系统不进入本 Slice。

2. 领域模型

术语定义关键区别
Tool Capability稳定 Tool identity 与 major contract。Agent Grant 指向 Capability，而非实现 Revision。
Tool RevisionCapability 的不可变、已审查实现和 effect/recovery/risk 声明。Invocation 解析并固定实际 Revision。
Model Tool Request模型提出的候选 Tool 操作。没有执行权限；不是 Tool Call。
Tool CallTool Runtime 校验、授权并持久接受的精确请求。一个 Tool Call 可有多个 Dispatch Attempt。
Tool Outcomesuccess、denied、classified failure 或 uncertain 的归一化结果。不暴露 Credential 或原始 Provider Error。
Approval Subject输入、Tool Revision 和 authority context 固定的不可变对象。变化即产生新 Subject。
Employee Confirmationinitiating Employee 对精确 Subject 的一次性确认或拒绝。确认意图，不扩大权限。
Interrupt等待外部响应的持久暂停。跨 Browser 连接和 Worker Lease 存续。
Waiting Run有未解决 Interrupt、当前无 Agent 执行的非终态 Run。仍可取消。

5. Tool Capability、Revision 与 Grant

决定：Agent Revision 授予稳定 Capability major version；Invocation 开始时解析到 active Tool Revision，并固定到恢复结束。
  • 兼容实现修复不要求发布新 Agent Revision。
  • 操作范围、Credential scope、数据访问、effect 或 contract major 扩大时创建新 Capability major，并重新授予。
  • Provider discovery metadata 不是 effect/recovery/risk 的权威来源。
  • 最终模型可见集合为 Catalog active Revision、Agent Grant、Principal baseline entitlement、Invocation restriction 与 Policy 的交集。

6. Model Step 与顺序 Tool Loop

  1. Agent Engine 向 Model Gateway 提交 Provider-neutral transcript 与可见 Tool projection。
  2. Model Gateway 建立并审计一个 ModelCall，流式收集文字和 Model Tool Request。
  3. 只有 Model Step 正常 finish 且 usage 持久化后，候选 Tool Request 才可交给 Tool Runtime。
  4. 多个 Tool Request 按模型返回顺序执行；同一时刻最多一个 Provider 调用。
  5. Tool Outcome 写回 Provider-neutral transcript，再开始下一 Model Step。
  6. 最多 5 个 Model Step、8 个 ToolCall；超限为 execution_limit_exceeded。

Model Step 失败时，候选 Tool Request 全部丢弃；部分文字按 generation/reset 撤回。Fallback 从该 Step 之前的同一 transcript 开始，不拼接 Primary/Fallback 请求或输出。

7. Employee Confirmation

  1. Tool Runtime 验证输入、Capability/Revision、Agent Grant、Principal baseline entitlement 与 Policy。
  2. Policy 返回 allow_with_employee_confirmation。
  3. Governance 持久化 Approval；Tools 持久化等待中的 ToolCall。
  4. Execution 写 Checkpoint、创建 tool_confirmation Interrupt，并把 Run 置为 waiting。
  5. initiating Employee 可确认、拒绝或单独取消 Run。
  6. 确认后重新授权，再签发 Credential Lease 并 dispatch；拒绝则产生 denied/employee_rejected Outcome。
  • 不支持他人审批、经理审批或审批 entitlement。
  • Confirmation 不自动过期，也不冻结授权。
  • Approval 与 Interrupt 分属 Governance/Execution，由 Server 幂等 Coordinator 串联，不跨表 JOIN/FK。
  • 拒绝不是 Run failure 或 cancellation；Agent 可解释或选择替代方案。

8. 未知副作用与取消

场景第一版行为
read-only / safe retry按 Tool Revision recovery 声明和 Policy 决定重试。
idempotency key同一 ToolCall 的 Dispatch Attempt 复用稳定 key。
reconciliation优先查询外部状态，不直接重试。
未知非幂等结果requires_review + tool_outcome_review Interrupt。
Employee 处理 unknown仅“带着不确定性继续”或取消 Run；不可手工改成成功/失败，不可直接重试原 ToolCall。
等待确认时取消立即取消，Provider 不执行。
Provider in-flight 时取消临时返回 409；Tool boundary 完成后恢复可取消。
output_ready 后取消继续沿用 Slice 1–2 的永久 too-late 语义。

9. Checkpoint 与恢复

Checkpoint 由 Execution Module 在本 Slice 增量实现，不等待独立 Slice。安全点包括 ToolCall 完成后、创建 Interrupt 前，以及 Confirmation 解决后恢复模型前。

Checkpoint {
  schemaVersion
  engineKind / engineVersion
  modelStepNumber / toolCallCount
  providerNeutralTranscript
  completedToolCallIds
  currentApprovalId / currentInterruptId
  remainingModelToolRequests
  outputGeneration
}

Tool input/output 的权威 payload 留在 Tools Module；Checkpoint 保存恢复所需 projection 与 ToolCall ID。恢复不得重新执行已完成 ToolCall，也不得重新请求模型生成已确认请求。

11. 状态与 Contract

Run 新增非终态 waiting；Invocation 新增 interrupted。具体等待原因由 active Interrupt 表达。

activeInterrupt: {
  id,
  kind: "tool_confirmation" | "tool_outcome_review",
  status: "pending",
  safeSubjectSummary,
  allowedResponses
}

Canonical events 包含 Tool lifecycle、interrupt.requested/resolved、run.waiting/resumed。SSE 继续使用 Run sequence；AI UI Presenter 只映射为 CMaster data parts。

12. Baseline Policy 与 Principal Entitlement

决定：CMaster 不建设本地逐 Principal/逐 Tool RBAC。Slice 3 只消费通用 enterprise_assistant.use_governed_tools entitlement；细粒度业务权限来自企业 IAM/Policy，目标系统继续最终授权。

Policy Adapter 固定、类型安全、deny-by-default，版本为 slice3-baseline-v1：

  • 缺 entitlement、Grant、active Revision：deny。
  • current_time、text_statistics：allow。
  • http.fetch：allow with Employee Confirmation。
  • 未知组合：deny。

14. Provider Host 与延后能力

Slice 3 只定义 child-process request/response、request ID、timeout、cancel、进程退出和非法响应处理。Contract Test 使用仓库固定 Fake executable；生产 Composition Root 不允许配置任意 executable。

Agent Skills Parser、Legacy Adapter、MCP、安装验证、供应链安全、网络/文件系统/资源沙箱和 Provider 生命周期完整移入首里程碑后的 Agent Skills & Isolated Provider Management Slice。

15. 版本与 Feature Flag

  • 同一个 Development Agent 新增 Revision v3；v1 Echo、v2 AI SDK text 保持不变。
  • 新增 Tool-enabled Model Profile ID，明确 toolCalling: true；可指向相同底层模型。
  • CMASTER_TOOL_RUNTIME_ENABLED 默认 false，并要求 Next Architecture + AI SDK Runtime。
  • Flag 关闭时不挂载 Tool/Confirmation 行为，原 Slice 2 路径不变。

16. 确认的测试 Seam

  1. Governance Interface：Policy、Approval、幂等及 PostgreSQL Adapter。
  2. Tool Runtime Interface：可见集合、Ledger-before-dispatch、Confirmation、Credential、Outcome 与 PostgreSQL Adapter。
  3. Agent Engine Interface：顺序 Tool Loop、limits、checkpoint/resume，使用 Fakes。
  4. Execution/Run Contract：waiting、Interrupt、取消、SSE replay 与 PostgreSQL Integration。
  5. Model Adapter Contract：AI SDK Tool 映射和本地 Fake OpenAI-compatible Provider。
  6. UI Projection：确认、拒绝、uncertain continuation、取消与刷新恢复。

Provider Host 作为 Tool Provider Adapter fixture 测试；不测试私有 SQL、类内部方法、AI SDK internals 或过渡 Tool 实现细节。

17. 验收

  • 未授权 Tool 不因模型伪造、Agent 变化或恢复而执行。
  • 任何 Provider I/O 前已有 ToolCall Ledger 和稳定 idempotency key。
  • Employee Confirmation 可跨刷新、SSE 断线和 Worker Lease 恢复。
  • 已完成 ToolCall 不被恢复路径重复执行。
  • 未知非幂等结果进入 requires_review，且 UI 不假定成功/失败。
  • Provider Host 崩溃不退出 API/Worker 主进程。
  • AI SDK、Credential、Tool payload 和原始 Error 不泄漏到 Domain/Public Event/Trace。
  • Feature Flag 关闭时 Slice 2 行为与 Contract 保持有效。
