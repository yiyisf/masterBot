Context & Artifacts

在 Governed Tool Runtime 上建立可审计、可恢复的 Invocation Context，以及内容寻址、版本不可覆盖、可被后续 Run 复用的 Text/Markdown Artifact。

1. 主验收场景

  1. Employee 在已有 Conversation 中发送第二个 Trigger Message，并创建 Run。
  2. Worker 领取 Run；Context Builder 只读取截至 Trigger Message 的历史。
  3. 短历史保留原文；超预算时生成较早历史的 Context Summary，并保留最近完整 Turn。
  4. Context Manifest 固定来源、hash、预算和纳入方式；Agent Engine 只消费构建结果。
  5. 模型经 Governed Tool Runtime 调用 cmaster.artifact.create_text。
  6. Artifacts Module 创建私有、不可变 Version 1，ToolOutcome 返回 Artifact Reference。
  7. Harness 确定性把引用附加到最终 Assistant Message。
  8. 刷新或 Worker 重启后，Employee 仍可预览、下载或 Range 读取确切 Version。
范围原则：主流程中的 Organization 隔离、Principal 权限、幂等、Worker 恢复、不可变版本和内容安全属于首版正确性；上传、复杂预览、删除、多级摘要等没有当前调用者的能力只记录，不深度设计。

2. 领域语言

术语本 Slice 含义不得混用
Conversation完整、员工可见的 Message 历史事实。不是模型 Context，也不执行摘要。
Invocation Context为一次 Invocation 构造的有限、受 Policy 约束、Engine-neutral 投影。不是 Conversation History 副本。
Context Summary对明确来源区间的有损派生压缩。不是 Message、Memory、Knowledge 或指令。
Context Manifest记录一次 Invocation 实际使用哪些来源、hash、预算和纳入方式的不可变记录。不保存 Message/Artifact 正文。
Artifact持久、版本化、可复用的工作输出。不是 Tool Outcome 或 Message 附件。
Artifact Reference指向一个确切 Artifact Version 的稳定引用。不是 latest-version link、内容或 storage key。

5. Context 一致性边界

决定：Run 只读取同 Conversation 中 sequence <= triggerMessage.sequence 的 Message。Run 接受后追加的 Message 不改变该 Run，恢复也不重新读取“最新历史”。

Context Builder 在 Worker 获得 Lease 后、Agent Engine 开始前执行。Conversations 回答“实际说过什么”，Context Builder 回答“本次 Invocation 应看到什么”。

Run A trigger = Message sequence 3

Message 1 ─ Message 2 ─ Message 3 ─ Message 4
                         ▲           ✕
                    Run A 上界   属于后续 Run

(organizationId, invocationId) 对 Context Manifest 唯一。Manifest 先提交、Execution 后记录引用；中间崩溃时恢复返回同一 Manifest，不重复选择或摘要，不使用分布式事务。

6. 预算与压缩算法

决定：采用 Pi/主流 Agent 可验证的基础模式——主动 token 阈值、从后向前保留最近完整 Turn、较早连续历史结构化摘要、完整历史与模型投影分离。
usableInput = min(
  Context Policy limit,
  Primary context window,
  Fallback context window (if configured)
) - enforced maxOutputTokens - safetyMargin
  1. 先预算 Agent instructions 和 Tool contracts。
  2. 完整保留 Trigger Message；放不下则 context_input_too_large，不截断。
  3. 从最新向前保留完整 Employee/Assistant Turn，并按权限展开其中 Text/Markdown Artifact。
  4. 把剩余较早连续历史生成一份 Context Summary。
  5. 极端历史若连一次 Summary 请求也无法容纳，明确失败；不静默丢弃。

首版不引入 tokenizer family。估算使用 UTF-8 bytes、消息结构开销与固定安全余量，Manifest 明示为 estimate；Provider 真实 usage 仍由 Models 记录。

Pi 的 chars/4、Coding file tracking、Session 级滚动 compaction、thinking 摘要不直接复制。未来正式 Coding Agent 可通过独立 Summary Profile 参考 Pi 的 Goal、Progress、Key Decisions、Next Steps、Critical Context 和文件操作追踪。

7. Context Summary 与信任边界

## Employee Goal
## Explicit Constraints
## Established Facts
## Decisions and Commitments
## Relevant Artifacts
## Unresolved Items
  • 摘要通过 Models Module；禁用 Tool，ModelCall 标记 purpose=context_summary，记录 Profile/usage。
  • 首版复用 Run Primary 和受限 Fallback，不增加独立 Summarizer Catalog。
  • Artifact 和 Summary 都是低信任参考资料；其中的命令不能覆盖 Agent Revision 或 Employee 当前请求。
  • 不处理或展示 raw Chain-of-Thought，不记录 Credential、Provider raw error 或 Policy 内部细节。
  • Context Manifest/Summary 正文不开放 Browser REST；UI 只看到计数、是否摘要和 Policy version。

8. Manifest 与 Checkpoint

ContextManifest {
  id, organizationId, invocationId
  triggerMessageId, triggerSequence
  contextPolicyVersion
  budget, estimatedUsage
  items[]: {
    sourceType, sourceId, sourceSequence?
    contentHash, trustClass
    inclusionMode: "verbatim" | "summary"
  }
  summaryId?
}

Manifest 不保存 Message/Artifact 正文。首次 build 返回内存 Invocation Context；恢复按引用重新读取并校验 hash。Hash 不进入 Browser Event 或普通 telemetry。

决定：Checkpoint 保存 contextManifestId 和 Invocation 开始后的模型/Tool 增量；不复制基础 Context。Artifact Tool 增量只保留 Artifact Reference。

9. Artifact 产品入口

决定：首个真实 Artifact 入口是低风险、无需 Employee Confirmation 的 cmaster.artifact.create_text。
{
  title: string;                    // 最多 200 字符
  format: "plain_text" | "markdown";
  content: string;                  // UTF-8，最多 48 KiB
}

Server 推导 text/plain; charset=utf-8 或 text/markdown; charset=utf-8。超过限制分类失败，不截断。Capability 仍经过 Principal Entitlement、Agent Grant、active Revision、Policy、Ledger 和输入验证。

Artifact Tool Provider Adapter 位于 Artifacts Module并调用其公开创建行为；Tools 不理解 Artifact 表，Server 只注册组合。每次 Tool 只创建新 Artifact + Version 1。createVersion 由 Module Interface/测试证明不覆盖，产品更新 Tool 和编辑 UI 后置。

10. Artifact 写入与恢复

  1. exclusive staging write
  2. UTF-8、大小、media type 校验
  3. 计算 SHA-256
  4. 原子提升到 blobs/sha256/{aa}/{bb}/{hash}
  5. ArtifactContent、Artifact、Version 在一个 PostgreSQL 事务提交
  • 数据库只记录已正式可用 Content，不暴露 staging 状态。
  • 同 Organization、相同 bytes/media type 复用 ArtifactContent/Blob；跨 Organization 物理去重不属于本 Slice Contract。
  • (organizationId, sourceToolCallId) 唯一并校验 request hash。Artifact 已提交但 ToolOutcome 未记录时，恢复返回原 Artifact；不同输入冲突。
  • promote 后 metadata 前崩溃最多留下 orphan Blob；完整 GC 后置。过期 staging 在本 Slice 可清理。
  • API/Worker 分角色运行时共享 CMASTER_ARTIFACT_STORAGE_ROOT；路径只存在于 Adapter。

11. Artifact 权限、引用与最终输出

  • Artifact 默认由 initiating Principal 私有；同 Organization 的其他 Principal 也不得读取。
  • Artifact 记录 createdForPrincipalId、createdByInvocationId、sourceToolCallId。
  • Message 固定 artifactId + artifactVersionId，不跟随 current Version，也不复制 title/content/media type。
  • 入选历史 Message 的可读 Text/Markdown Artifact 由 Context Builder 受控展开，内容计入预算并保留 provenance。
  • Harness 收集成功 Artifact ToolOutcome，按完成顺序去重，并与最终文本一起固定在 output_ready。
  • 不从模型自然语言解析 ID。Worker 在 output_ready 后崩溃仍幂等追加相同 Message Parts。
  • Run 最终失败不创建成功 Assistant Message；已创建 Artifact 与 ToolCall 审计事实保留，失败产物 UI 后置。

12. REST、Range 与最小 UI

Browser 只开放 Artifact metadata、指定 Version metadata、指定 Version 内容读取；不提供创建、更新或删除 Command。

请求行为
无 Range200，完整内容
bytes=100-199206，闭区间
bytes=100- / bytes=-100206，open-ended / suffix
非法、越界、多区间416；不生成 multipart

所有读取使用相同权限检查并返回 Accept-Ranges、Content-Range、Content-Length 与安全 Content-Type。Contract 不暴露 hash、storage key 或 path。

Slice 4 在现有 Run/Message 页面提供安全 Text、Markdown Renderer 和 unknown fallback/download card。Markdown 禁用 raw HTML、脚本和危险链接。Slice 5 完成 Artifact 列表、导航、版本交互、正式布局与可访问体验。

13. Events、Telemetry 与失败

事件/失败安全字段或语义
invocation.context_builtInvocation/Manifest ID、message/artifact count、summaryUsed、estimatedInputTokens、Policy version
artifact.createdInvocation/ToolCall/Artifact/Version ID、kind、media type
context_input_too_large不可省略输入超预算；non-retryable
context_build_failed来源、摘要、hash 或持久化失败；内部分类决定 retryability

Run Event、日志和 Trace 不记录 Prompt、Summary/Artifact 正文、content hash、Tool input、Provider raw error 或 storage key。Artifact 创建由 provenance、Tool Ledger 和 Run Event 追踪；持久逐次下载 Audit Record 留到 Slice 6，读取 telemetry 仅记录安全 ID、结果和字节数。

14. Revision、Profile 与 Feature Flag

  • 创建新的不可变 Slice 4 Development Agent Revision，固定 baseline Context Policy 并增加 Artifact Tool Grant；不修改 Slice 3 Revision。
  • 创建新的不可变 Model Profile IDs，显式固定 contextWindowTokens 与 maxOutputTokens；AI SDK Adapter 实际施加 max output。
  • Primary/Fallback Context Window 都参与最小预算，避免 Fallback 临时改变 Manifest。
  • CMASTER_CONTEXT_ARTIFACTS_ENABLED 默认 false，并依赖 Next Architecture + AI SDK Runtime + Tool Runtime。
  • Flag 关闭时不创建 Manifest、不挂载 Artifact 路由，并保持 Slice 3 行为。

15. 否决方案与理由

否决方案理由
Conversation 自己摘要混淆完整历史事实与一次 Invocation 投影。
Agent Engine 临时截断历史Manifest 无法审计，恢复/Fallback 输入漂移。
Provider-side compaction 为权威Provider 锁定且 provenance 不足；未来仅可作 Adapter 优化。
Run/Checkpoint 复制历史正文多权威写路径、敏感内容扩散、恢复不一致。
自动把所有模型文本变成 ArtifactArtifact 意图不明确，产生噪音；使用显式 governed Tool。
模型在自然语言中返回 Artifact ID不可靠、不可恢复；Harness 使用结构化 Outcome。
Message 指向 latest Artifact后续版本会改写历史 Message 含义。
同 Organization 即可读取无法阻止员工横向访问；首版创建者私有。
本 Slice 完整实现 quarantine/derivative/trash没有上传、预览、删除调用者，会制造空状态和无验收流程。
独立摘要模型与精确 tokenizer增加 Catalog/Policy/依赖复杂度；缺少当前成本与质量证据。

16. 核心测试与验收

  1. Context Contract：Trigger 边界、短历史原文、Summary + 最近 Turn、Manifest 引用/hash、不复制正文。
  2. Context 恢复：Manifest 后崩溃，恢复复用同一 Manifest/Summary；新 Message 不污染原 Run。
  3. Artifact Contract：Version 不覆盖、sourceToolCallId 幂等冲突、同 Organization 内容复用。
  4. Storage Adapter：staging/promote/metadata 顺序、重启可读、过期 staging 清理、完整/Range read。
  5. Tool/Worker E2E：Artifact 提交后 ToolOutcome 前崩溃不重复创建；最终 Message 含确切 Version Reference。
  6. HTTP/UI：创建者可读、同组织他人不可读、路径不泄漏、Text/Markdown 与 unknown fallback。
npm run next:check
npm run next:test:integration

真实付费 Summary/Agent Smoke 继续显式启用且默认 skip。测试优先通过 Module public Interface、Adapter Contract、PostgreSQL Integration 和 UI Projection，不断言私有 SQL 或框架内部实现。

17. 实施顺序

决定：一个 refactor/context-artifacts PR，按可审查、持续通过 Build/Test 的提交推进；Slice Flag 在完整可用前保持关闭。
  1. Contract、Package、Migration 与 Revision/Profile limits。
  2. Context Builder、Summary、Manifest、预算与恢复。
  3. Artifact Module、本地存储、幂等与权限。
  4. Artifact Tool、Harness、Checkpoint、output_ready 与 Message Reference。
  5. REST、Range、Renderer Registry。
  6. PostgreSQL Integration、恢复测试、生成物与文档。
