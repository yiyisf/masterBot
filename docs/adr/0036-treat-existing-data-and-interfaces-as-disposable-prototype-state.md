# Treat existing data and interfaces as disposable prototype state

The current system has only been used for local technical validation, so the refactor has no requirement to migrate existing SQLite records, preserve active Harness instances, or maintain backward compatibility for current HTTP, SSE, database, or `ExecutionStep` contracts. New modules may start with clean PostgreSQL schemas and versioned interfaces, and local prototype databases may be archived or reset. Incremental vertical slices still control engineering risk, but compatibility adapters are used only when they simplify temporary code replacement and are removed promptly; built-in Skills, Agent examples, and other useful assets are deliberately re-authored or imported as seed content rather than treated as historical customer data.
