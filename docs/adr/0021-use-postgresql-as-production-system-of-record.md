# Use PostgreSQL as the production system of record

The refactored enterprise Web server will use PostgreSQL as the authoritative production store for module state, transactions, ordered Run Events, Checkpoints, and the Outbox. SQLite may provide a lightweight development and debugging adapter, but PostgreSQL defines production concurrency and transactional semantics, CI integration tests must run against PostgreSQL, and adapters share behavioral contract tests rather than forcing SQL-dialect portability. Domain and contract models remain independent of database or ORM types, each module owns its schema and repositories, cross-module table reads are prohibited, Artifact bytes remain in content storage, and existing SQLite data is imported through a migration tool rather than keeping SQLite as a second production target.
