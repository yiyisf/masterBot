# Separate API and Worker runtime roles with replayable SSE

The modular monolith will ship as one codebase that can run `api`, `worker`, or development `all` roles. API nodes accept commands, persist Runs and dispatch records, serve queries, and stream events; Worker nodes lease Runs from a PostgreSQL-backed dispatcher, heartbeat, execute the Harness, checkpoint, and append ordered Run Events, so browser disconnects and API deployment do not cancel execution. Browsers use HTTP commands plus replayable SSE with Run sequence numbers and `Last-Event-ID`; PostgreSQL Run Events are durable truth, `LISTEN/NOTIFY` is only the initial live wake-up adapter, token output is coalesced before persistence, and polling is a fallback. A replaceable live-event-bus seam permits Redis Streams, NATS, or another broker later without changing browser or domain contracts.
