# Keep policy evaluation behind a stable module

Authentication claims are inputs to, not substitutes for, authorization. A stable Policy Module will evaluate Organization, Principal, delegation chain, Agent Revision, Run or Invocation, resource, action, data classification, and environment and return a versioned decision with reasons and enforceable obligations such as approval, redaction, model restriction, network restriction, output limits, or enhanced audit. The first adapter will evaluate typed in-process policies with deny-by-default behavior; OPA, Cedar, or an enterprise policy platform will be added only when their operational and language capabilities are needed. Harness and Tool Runtime enforce decisions without knowing the policy language or receiving credentials.
