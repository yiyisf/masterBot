# Organize the modular monolith as workspace modules

The repository will use npm Workspaces with `apps/server` as the API/Worker/all composition root, `apps/web` as the Next.js frontend, and business modules for identity, conversations, execution, agents, models, tools, context, artifacts, automation, and governance. Each module owns its domain, application behavior, adapters, storage schema, and one public interface; package exports and lint rules prohibit deep and cross-module imports. A small kernel contains only genuinely universal primitives, external versioned contracts remain separate from domain types, adapters stay with the behavior they support for locality, and migration moves code only as each vertical slice replaces behavior rather than performing an upfront directory rewrite.
