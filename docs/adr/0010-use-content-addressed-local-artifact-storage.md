# Use content-addressed local storage for initial Artifact content

The first Artifact content adapter will write immutable blobs beneath `data/artifacts/blobs/sha256/{first-2}/{next-2}/{hash}`, using per-Run staging files, quarantine for content awaiting checks, derivative directories for previews, and delayed trash collection. Artifact and version records reference stable content records rather than paths; content records hold the adapter-specific key, hash, media type, size, and status. Writes are staged, hashed, checked, atomically promoted, and then committed in metadata, while unreferenced blobs are removed only by garbage collection. This provides integrity, deduplication, and a migration path to object storage without making filesystem layout part of the domain contract.
