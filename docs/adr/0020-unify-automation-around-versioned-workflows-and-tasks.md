# Unify automation around versioned Workflows and Tasks

A Plan remains temporary Working State inside a Run and is promoted explicitly into durable Tasks only when work needs queuing, assignment, dependency, retry, background, or human-tracking lifecycle. A Workflow is an immutable versioned automation definition; each Workflow Execution coordinates a Task dependency graph whose attempts may start Runs, invoke governed Tools, or wait for people. Schedules and webhooks only create Triggers, DAG is a structural representation rather than a separate domain object, Runbooks add operational risk, approval, evidence, and rollback policy to the same Workflow engine, and RPA remains a Tool capability. This consolidates the current Agent DAG, Workflow, Runbook, Scheduler, and requirement automation paths without confusing Harness Runs with Workflow Executions.
