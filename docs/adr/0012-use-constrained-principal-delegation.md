# Use constrained Principal delegation for Agent execution

Agents act on behalf of the initiating Principal rather than receiving broad independent identity rights, and each child Invocation may preserve or reduce but never expand its parent's effective authority. Tool Runtime evaluates every invocation against the intersection of Organization policy, Principal entitlements, Agent Tool grants, Tool policy, and Run or Invocation restrictions; scheduled and system work uses an explicit Service Principal. Credentials are issued as short-lived, narrowly scoped leases instead of being carried by the Harness, and audit records identify the initiating Principal, complete Agent delegation chain, and executing Tool. This prevents Agent configuration or subagent delegation from becoming a privilege-escalation path.
