# Migrate by incremental vertical slices

The refactor will replace legacy behavior through production-shaped vertical slices that can be integrated, observed, feature-flagged, and rolled back independently, rather than completing all phases on a long-lived branch and merging once. Each capability has one authoritative write path, compatibility occurs through explicit legacy adapters or one-time migrations rather than indefinite dual writes, and obsolete implementation and tests are deleted after replacement acceptance. Existing planning documents are historical input only; the decisions and final target plan produced by this design session become the normative direction, and older documents will be marked non-normative rather than silently treated as current specifications.
