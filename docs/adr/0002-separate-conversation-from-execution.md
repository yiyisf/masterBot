# Separate conversation history from execution lifecycles

CMaster Bot will model a continuing Conversation and its immutable Messages separately from each Run that handles an employee submission. A Run contains a tree of Agent Invocations, model calls, tool executions, and events; provider continuation identifiers remain Engine Sessions inside engine adapters, while durable queued or background work is represented as a Task. Runs reference canonical Messages and normally persist a context manifest rather than copying conversation history, with full content-addressed context snapshots retained only when replay, recovery, or compliance policy requires them. This avoids the current overloaded `sessionId` model and keeps UI history, Harness lifecycle, and provider state independently evolvable.
